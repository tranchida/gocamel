Version **v0.14.0**, dated October 3, 2026, is a security and reliability release with the fixes from the 2026-09 and 2026-10 security and code reviews. Some defaults changed: read [Upgrade notes](#upgrade-notes) before upgrading.

## Upgrade

Upgrade the core and each optional module you use together:

```bash
go get gitlab.com/tranchida/gocamel@v0.14.2
go get gitlab.com/tranchida/gocamel/components/kafka@v0.14.2
```

Use [v0.14.2](../v0.14.2/): the component and observability `v0.14.0` and `v0.14.1` tags still require core v0.13.1, so the Kafka, STOMP and gRPC components, which use APIs added in this release, do not build at those versions unless you also require core v0.14.0.

## Upgrade notes

- **`direct:` and `ErrStopRouting`**: a Filter, an incomplete Aggregator, a Resequencer or a handled dead letter in a route called through `direct:` now only ends that route, and `DirectProducer.Send` returns `nil`. The `Stop()` EIP still ends the whole exchange (`CamelRouteStop` property, `Send` returns `ErrStopRouting`).
- **Kafka/STOMP**: a message whose route keeps failing is logged and committed/acknowledged after 10 redeliveries (`maxRedeliveries`, about 80 s). Use a `DeadLetterChannel` to keep it, or `maxRedeliveries=-1` to retry forever.
- **Parallel Split/RecipientList**: at most 10 branches run at a time. Raise the bound with `MaxConcurrency(n)`.
- **exec**: a `CamelExecCommandExecutable` header may only select the endpoint's executable or a name listed in the new `allowedExecutables` option.
- **SQL**: a query is rejected if it stacks statements under either quoting rule, so `\'` inside a literal is refused; escape quotes with `''`.
- **ManagementServer**: requests with a `Host` other than an IP address or `localhost` are rejected unless allowed with `SetAllowedHosts`, cross-origin browser POSTs are rejected, and starting a route while the context is stopped returns `409`. `Start` now returns bind errors.
- **HTTP producer**: a client's unchanged `Authorization`/`Cookie` is no longer relayed upstream; opt in with `HTTPComponent.SetForwardInboundCredentials(true)`.

## Security

- **ToD option injection**: templates are resolved with the new `InterpolateURI`, which escapes exchange values by position; a header could previously add `allowHeaderOverride=true` to an `exec:` or `sql:` endpoint.
- **Inbound `Camel*` headers**: the HTTP, Kafka, STOMP and gRPC consumers drop them (new `IsCamelHeader`), and the HTTP consumer no longer emits them in responses.
- **HTTP**: the producer no longer forwards response-only headers (`Set-Cookie`, `Server`...) on chained calls.
- **Template `json`**: HTML-safe encoding, fixing an XSS.
- **Bounded resources**: LRU `ProducerCache` (`SetProducerCacheSize`, default 1000), TCP consumer `maxConnections` (default 1024), bounded parallel fan-out.
- **ManagementServer**: DNS rebinding and CSRF protection, optional bearer token (`SetAuthToken`), no internal error details in responses.

## Fixed

- SEDA/chan consumers run exchanges under their own context and drain their queue on `Stop` (`shutdownTimeout`).
- Kafka/STOMP redeliveries use an exponential backoff, and dead-lettered messages are committed instead of redelivered; Kafka retries transient fetch errors instead of stopping.
- Aggregator completion timeouts are restored when a route starts (new `ListableAggregationRepository`).
- The Net textline producer and consumer agree on `\n` framing.
- `Route.Stop` stops nested stoppable processors, and `Resequencer.Stop` waits for an in-flight timeout delivery.
- The File producer publishes files atomically; the Dynamic Router feeds each step's reply to the next step.
- The ProducerCache no longer caches a producer created while the context was stopping.

See the [CHANGELOG](https://gitlab.com/tranchida/gocamel/-/blob/main/CHANGELOG.md) for the full list.

## Validation

All 21 workspace modules build, vet and pass `go test -race`; staticcheck and gosec are clean. Each fix has a regression test that fails without it.
