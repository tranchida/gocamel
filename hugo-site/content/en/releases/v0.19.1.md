Version **v0.19.1**, dated November 9, 2026, is a patch release for the consumer lifecycle, shutdown and queue-draining hardening introduced in v0.19.0. Every component and observability module at v0.19.1 requires core v0.19.1.

## Consumer Lifecycle

- **`Start()` / `Stop()` serialization**: HTTP, net, management, Redis, Telegram and file consumers now serialize concurrent lifecycle transitions. A `Stop()` racing a `Start()` waits for the consumer to be fully up and then tears it down, instead of observing `started == false` and returning early.
- **`FileConsumer` restart**: removed the one-shot `sync.Once` from `Stop()`. A consumer can now be started, stopped, and started again without the second `Stop()` blocking forever on a watcher whose stop channel is never closed.

## Bounded Shutdown

- **FTP / SFTP / SMB / POP3**: the active transport is force-closed before waiting for the polling goroutine, so a server that accepts a connection but never answers cannot block `Stop()` (and route/context shutdown) indefinitely. SFTP and SMB track the connection used by the current poll, including `disconnect=true` mode.
- **SFTP handshake**: the SSH/SFTP handshake is now bounded by `connectTimeout` and the underlying TCP connection is published before the handshake so shutdown can abort it.
- **`seda` / `chan`**: in-flight `Send()` calls are tracked and awaited before the final queue drain. A producer can no longer drain messages belonging to another concurrent producer or to a restarted consumer.

## Documentation and Deep Copy

- Extended `deepCopyValue` with primitive numeric/bool slices, `[][]byte` and primitive-string-keyed maps.
- Documented the OpenTelemetry `ErrStopRouting` context behavior and the `ManagementServer` lifecycle (stopped by `CamelContext.Stop()`, not restarted automatically by `CamelContext.Start()`).
