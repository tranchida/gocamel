Version **v0.13.0**, dated September 5, 2026, adds archive data formats with password support and the new STOMP/ActiveMQ component.

## Upgrade

Upgrade the core and each optional module you use together:

```bash
go get gitlab.com/tranchida/gocamel@v0.13.0
go get gitlab.com/tranchida/gocamel/components/stomp@v0.13.0
```

All published components and observability modules have matching `v0.13.0` tags and require the core `v0.13.0`.

## New: STOMP/ActiveMQ component

Produce and consume messages with any STOMP 1.0/1.1/1.2 compliant broker (ActiveMQ, ActiveMQ Artemis, RabbitMQ, Apollo) via the `go-stomp` client:

```go
import "gitlab.com/tranchida/gocamel/components/stomp"

ctx.AddComponent("stomp", stomp.NewStompComponent())

builder.From("stomp://queue/orders?host=localhost:61613&ack=client-individual")

builder.To("stomp://queue/orders?host=localhost:61614&ssl=true&sslCAFile=/etc/gocamel/ca.pem")
```

- Consumer ack modes `auto` (default), `client` and `client-individual`: messages are acknowledged only after successful processing, failures are retried before any ack.
- SSL/TLS: `ssl=true` with `sslCAFile` (custom CA), `sslCertFile`/`sslKeyFile` (mutual TLS), `sslServerName` (SNI override) and a warned `sslInsecureSkipVerify` opt-in.
- `forwardHeaders` allowlist and `allowHeaderOverride` opt-in for dynamic destinations; sensitive credential headers are never forwarded to the broker.

## New: ZIP and tar.gz data formats

`MarshalZip`/`UnmarshalZip` and `MarshalTarGz`/`UnmarshalTarGz` DSL methods, implemented with the standard library only:

- ZIP marshal writes standard deflate archives or WinZip AE-2 AES-256 encrypted entries (`ZipPassword`); UnmarshalZip reads plain, ZipCrypto (legacy `zip -P`) and WinZip AES archives.
- Single-entry archives unmarshal to raw content, multi-entry archives to `map[string][]byte`.
- zip-slip/tar-slip entry names are rejected on both marshal and unmarshal; per-entry decompression size limits (512 MiB default) guard against zip bombs; password checks are constant-time.

## Validation

All module builds, vet and race-detector tests pass; the STOMP component is tested in-process against the embedded go-stomp server over plain TCP, TLS and mutual TLS.
