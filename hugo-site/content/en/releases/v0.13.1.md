Version **v0.13.1**, dated September 12, 2026, is a security patch for the ZIP and tar.gz data formats.

## Upgrade

Upgrade the core and each optional module you use together:

```bash
go get gitlab.com/tranchida/gocamel@v0.13.1
go get gitlab.com/tranchida/gocamel/components/stomp@v0.13.1
```

All published components and observability modules have matching `v0.13.1` tags and require the core `v0.13.1`.

## Fixed

- **WinZip AES reader**: HMAC is computed over the ciphertext bytes actually read (`p[:n]`) and verified when the payload is consumed, including `io.EOF` and empty entries. AE-2 stores no CRC, so a skipped MAC could accept a truncated stream.
- **ZIP/tar marshal**: absolute entry names (`/etc/passwd`, Windows volumes) are rejected, matching unmarshal zip-slip rules.
- **ZIP/tar unmarshal**: in addition to the 512 MiB per-entry limit, archives are capped at 4096 regular-file entries and 1 GiB total decompressed size (`ZipMaxEntries` / `ZipMaxTotalSize` / `TarGzMaxEntries` / `TarGzMaxTotalSize`; non-positive values disable a cap).

## Validation

Core ZIP/tar/AES tests cover one-byte AES reads, large buffers, empty payloads, truncated ciphertext, absolute marshal names, and the new archive caps.
