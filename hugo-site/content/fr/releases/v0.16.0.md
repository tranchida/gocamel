La version **v0.16.0**, datée du 5 octobre 2026, est une version de fonctionnalités : le composant `mock` et l'advice de route pour tester les routes, les gestionnaires `OnException` par type d'erreur, et une Saga persistante avec timeout par étape et reprise après crash optionnelle. Elle ne contient aucun changement incompatible.

## Mise à niveau

Mettez à niveau le cœur et chaque module optionnel que vous utilisez, ensemble :

```bash
go get gitlab.com/tranchida/gocamel@v0.16.0
go get gitlab.com/tranchida/gocamel/components/kafka@v0.16.0
```

Chaque composant et module d'observabilité en v0.16.0 requiert le cœur v0.16.0.

## Composant mock et advice de route

Le nouveau composant `mock` (stdlib, enregistré par défaut) est un endpoint producteur uniquement qui enregistre une copie profonde de chaque échange qui lui est envoyé. `Route.AdviceWith` remplace les URI des `To()` statiques d'une route construite avant `Start()`, ce qui permet à un test de substituer des mocks aux vrais endpoints sans reconstruire la route :

```go
func TestOrderRoute(t *testing.T) {
    ctx := gocamel.NewCamelContext()
    route, err := ctx.CreateRouteBuilder().
        From("direct:in").
        SetHeader("source", "test").
        To("kafka:orders").
        Build()
    require.NoError(t, err)

    // Remplace le vrai endpoint par un mock entre Build et Start.
    require.NoError(t, route.AdviceWith(map[string]string{"kafka:orders": "mock:orders"}))

    mock, err := ctx.GetMockEndpoint("mock:orders")
    require.NoError(t, err)
    mock.ExpectedMessageCount(1) // au moins 1

    require.NoError(t, ctx.Start())
    t.Cleanup(func() { _ = ctx.Stop() })

    producer, err := ctx.GetProducer("direct:in")
    require.NoError(t, err)
    exchange := gocamel.NewExchange(context.Background())
    exchange.In.SetBody("order-1")
    require.NoError(t, producer.Send(exchange))

    require.NoError(t, mock.Wait(time.Second))
    assert.Equal(t, "order-1", mock.Body(0))
    source, _ := mock.Header(0, "source")
    assert.Equal(t, "test", source)
}
```

`AdviceWith` substitue aussi les branches multicast, Choice, LoadBalancer et Saga. Il renvoie une erreur une fois la route démarrée, ignore les URI inconnues et ne substitue ni `From()`, ni `ToD`, ni les autres envois dynamiques. Voir la page [composants](../../components/) pour l'API complète de `MockEndpoint`.

## OnException

`RouteBuilder.OnException(cibles...)` déclare des gestionnaires d'erreurs propres à la route, sélectionnés par type d'erreur, comme le `onException` d'Apache Camel. Les valeurs d'erreur correspondent via `errors.Is` ; les pointeurs non nuls vers un type d'erreur ou d'interface (`gocamel.ErrorType[*MyError]()`) correspondent via `errors.As`. La première clause correspondante, dans l'ordre de déclaration, l'emporte et remplace l'`ErrorHandler` de la route pour cette erreur :

```go
ctx.CreateRouteBuilder().
    OnException(gocamel.ErrorType[*ValidationError]()).
        Handled(true).              // arrête le routage, aucune erreur pour l'émetteur
        SetBody("invalid order").
        To("direct:invalid").
    End().
    OnException(io.ErrUnexpectedEOF).
        MaximumRedeliveries(3).     // relivre l'étape en échec
        RedeliveryDelay(100 * time.Millisecond).
        BackOffMultiplier(2).
        MaximumRedeliveryDelay(2 * time.Second).
        To("direct:recovery").
    End().
    From("direct:orders").
    To("http://backend/orders")
```

L'étape en échec est d'abord relivrée, puis les processeurs de la clause s'exécutent. `Handled(true)` arrête le routage sans renvoyer d'erreur à l'émetteur ; `Continued(true)` reprend à l'étape suivante. Les erreurs sans clause correspondante et les échanges déjà envoyés en dead letter conservent le comportement existant de l'`ErrorHandler`/`DeadLetterChannel`. Une cible absente ou invalide fait échouer `Build()`. Les clauses au niveau du contexte et `OnWhen` ne sont pas encore pris en charge. Voir la page [EIP](../../eip/) pour les détails.

## Saga persistante

L'EIP Saga enregistre désormais son état dans un `SagaRepository` après chaque étape terminée et chaque compensation, sous la clé de l'en-tête `CamelSagaId` (un UUID est généré s'il est absent). `MemorySagaRepository` est le défaut ; `SQLSagaRepository` (module racine, `database/sql` uniquement, table `gocamel_sagas`) survit à un crash du processus :

```go
db, err := sql.Open("sqlite", "sagas.db") // n'importe quel driver database/sql
if err != nil {
    return err
}
repo := gocamel.NewSQLSagaRepository(db, gocamel.SQLSagaOptions{})
if err := repo.InitDB(context.Background()); err != nil {
    return err
}

ctx.CreateRouteBuilder().
    From("direct:booking").
    Saga().
        Repository(repo).          // défaut : en mémoire, perdu à l'arrêt
        Timeout(5 * time.Second).  // borne chaque action et compensation
        RecoverIncomplete(true).   // compense les restes au CamelContext.Start
        Action("direct:reserve-hotel", "direct:cancel-hotel").
        Action("direct:reserve-flight", "direct:cancel-flight").
    End().
    To("direct:booked")
```

- `Timeout(d)` : une action qui le dépasse échoue avec `ErrSagaStepTimeout` et les étapes terminées sont compensées.
- `RecoverIncomplete(true)` (optionnel) : au `CamelContext.Start`, les sagas incomplètes sont compensées en commençant par la dernière étape. Désactivé, elles sont seulement signalées par un avertissement dans les logs. `SagaProcessor.Recover(ctx, camelCtx)` lance une reprise à la demande.
- Une compensation en échec reste dans le repository pour la reprise suivante. La compensation à la reprise est **au moins une fois** : les compensations doivent être idempotentes.
- Activez `RecoverIncomplete` sur une seule instance lorsque plusieurs processus partagent une même base.

{{% notice warning %}}
**Seules les compensations déclarées par URI (`Action(actionURI, compensationURI)`) peuvent être reprises après un redémarrage.** Une fonction Go ne peut pas être persistée : quand la reprise rencontre une compensation `ActionFunc`, elle signale `ErrSagaCompensationNotRecoverable` dans une ligne de log ERROR (jamais ignorée silencieusement) et conserve la saga dans le repository pour un traitement manuel. Déclarez avec `Action` chaque étape qui doit survivre à un crash.
{{% /notice %}}

## Corrections

- **Saga** : `ActionFunc(action, nil)` n'enregistre plus une fonction nil comme compensation (ce qui provoquait une panique, récupérée, lorsque l'étape devait être compensée) ; une compensation nil signifie désormais que l'étape n'a rien à annuler.

## Notes de mise à niveau

Aucun changement incompatible : les routes existantes se comportent comme en v0.15.0. Les sagas utilisent par défaut un repository en mémoire, ce qui conserve le comportement précédent en processus ; la seule différence visible est l'en-tête `CamelSagaId`, positionné sur l'échange lorsqu'il est absent.

Vous venez de la v0.14.x ? La v0.15.0 a rendu `allowHeaderOverride=true` obligatoire pour les surcharges par en-têtes d'Anthropic et d'Ollama : lisez d'abord les [notes de version v0.15.0](../v0.15.0/).
