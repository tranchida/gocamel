La version **v0.14.0**, datée du 3 octobre 2026, est une version de sécurité et de fiabilité qui regroupe les corrections des revues de sécurité et de code 2026-09 et 2026-10. Certains comportements par défaut changent : lisez les [notes de mise à niveau](#notes-de-mise-à-niveau) avant de mettre à jour.

## Mise à niveau

Mettez à niveau le cœur et chaque module optionnel que vous utilisez, ensemble :

```bash
go get gitlab.com/tranchida/gocamel@v0.14.2
go get gitlab.com/tranchida/gocamel/components/kafka@v0.14.2
```

Utilisez la [v0.14.2](../v0.14.2/) : les tags `v0.14.0` et `v0.14.1` des composants et des modules d'observabilité requièrent encore le cœur v0.13.1, si bien que les composants Kafka, STOMP et gRPC, qui utilisent des API ajoutées dans cette version, ne compilent pas dans ces versions sauf si vous requérez aussi le cœur v0.14.0.

## Notes de mise à niveau

- **`direct:` et `ErrStopRouting`** : un Filter, un Aggregator incomplet, un Resequencer ou une lettre morte traitée dans une route appelée par `direct:` ne termine plus que cette route, et `DirectProducer.Send` renvoie `nil`. L'EIP `Stop()` termine toujours tout l'échange (propriété `CamelRouteStop`, `Send` renvoie `ErrStopRouting`).
- **Kafka/STOMP** : un message dont la route échoue en boucle est journalisé puis commité/acquitté après 10 redélivraisons (`maxRedeliveries`, environ 80 s). Utilisez un `DeadLetterChannel` pour le conserver, ou `maxRedeliveries=-1` pour réessayer indéfiniment.
- **Split/RecipientList parallèles** : au plus 10 branches s'exécutent en même temps. Augmentez la borne avec `MaxConcurrency(n)`.
- **exec** : un en-tête `CamelExecCommandExecutable` ne peut choisir que l'exécutable de l'endpoint ou un nom listé dans la nouvelle option `allowedExecutables`.
- **SQL** : une requête est refusée si elle empile des instructions selon l'une ou l'autre règle d'échappement, donc `\'` dans un littéral est refusé ; échappez les apostrophes avec `''`.
- **ManagementServer** : les requêtes dont le `Host` n'est ni une adresse IP ni `localhost` sont refusées sauf autorisation par `SetAllowedHosts`, les POST cross-origin des navigateurs sont refusés, et démarrer une route alors que le contexte est arrêté renvoie `409`. `Start` renvoie désormais les erreurs de bind.
- **Producteur HTTP** : l'`Authorization`/`Cookie` inchangé d'un client n'est plus relayé en amont ; activez-le avec `HTTPComponent.SetForwardInboundCredentials(true)`.

## Sécurité

- **Injection d'options via ToD** : les templates sont résolus par la nouvelle `InterpolateURI`, qui échappe les valeurs de l'échange selon leur position ; un en-tête pouvait auparavant ajouter `allowHeaderOverride=true` à un endpoint `exec:` ou `sql:`.
- **En-têtes `Camel*` entrants** : les consumers HTTP, Kafka, STOMP et gRPC les ignorent (nouvelle `IsCamelHeader`), et le consumer HTTP ne les renvoie plus dans ses réponses.
- **HTTP** : le producteur ne transmet plus les en-têtes propres aux réponses (`Set-Cookie`, `Server`...) lors d'appels enchaînés.
- **Fonction `json` des templates** : encodage sûr pour le HTML, ce qui corrige une XSS.
- **Ressources bornées** : `ProducerCache` LRU (`SetProducerCacheSize`, 1000 par défaut), `maxConnections` du consumer TCP (1024 par défaut), fan-out parallèle borné.
- **ManagementServer** : protection contre le DNS rebinding et le CSRF, jeton bearer optionnel (`SetAuthToken`), aucun détail d'erreur interne dans les réponses.

## Corrections

- Les consumers SEDA/chan traitent les échanges sous leur propre contexte et vident leur file au `Stop` (`shutdownTimeout`).
- Les redélivraisons Kafka/STOMP suivent un backoff exponentiel, et les messages envoyés en lettre morte sont commités au lieu d'être redélivrés ; Kafka réessaie les erreurs de fetch transitoires au lieu de s'arrêter.
- Les timeouts de complétion de l'Aggregator sont restaurés au démarrage d'une route (nouvelle `ListableAggregationRepository`).
- Le producteur et le consumer Net textline s'accordent sur le délimiteur `\n`.
- `Route.Stop` arrête les processeurs imbriqués, et `Resequencer.Stop` attend une livraison sur timeout déjà en cours.
- Le producteur File publie ses fichiers de façon atomique ; le Dynamic Router passe la réponse de chaque étape à la suivante.
- Le ProducerCache ne met plus en cache un producteur créé pendant l'arrêt du contexte.

Consultez le [CHANGELOG](https://gitlab.com/tranchida/gocamel/-/blob/main/CHANGELOG.md) pour la liste complète.

## Validation

Les 21 modules du workspace compilent, passent `go vet` et `go test -race` ; staticcheck et gosec ne signalent rien. Chaque correction a un test de régression qui échoue sans elle.
